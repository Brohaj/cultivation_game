# Путь Культиватора — Контекст для Claude

## Что это
Инкрементальная idle-игра в жанре xianxia (cultivation). Vanilla JS, без фреймворков, один HTML-файл + подключаемые скрипты. Открывается через index.html в браузере. Основная версия: **0.7**.

Эта папка — выбранная основная версия 0.7 с учениками и новой кармой. Текущий вход — index.html; исторические описания прототипа относятся к разработке этой версии. Актуальные правила — [docs/prototype_report.md](docs/prototype_report.md); остальные большие справочники сохраняют исторические срезы. Единственный вход — `index.html`.

Вдохновение: Realm Grinder (prestige-петля), Perfect Keystroke (культивация), классические сянься-новеллы.

## Ключевые паттерны кода

- **Глобальный объект `game`** — всё состояние. Никаких классов, ООП или модулей
- **Добавление нового поля**: state.js → lifecycle.js reset() → save.js getSaveableState() + applyLoadedState() с дефолтом
- **События**: EVENTS.push({id, text, type, condition(g), effect(g), weight?}) в файлах data/events/
- **Техники**: TECHNIQUES.push({...}) в data/techniques.js, эффекты суммируются через getTechBonus(key)
- **Бонусы**: getTechBonus() + getArtifactBonus() + getSectBonus() + getFormationBonus() — все суммируются в formulas.js
- **UI**: innerHTML-рендер по вызову (renderX()), updateTickUI() обновляет бары/числа без перерисовки
- **Загрузка скриптов**: data/* → save.js → game/* → ui/* (порядок важен, нет import/export)
- **Сохраняемое состояние**: только JSON-данные. Эффект финального приключения восстанавливается по индексу шага/выбора, pendingRebirth фиксирует уже начисленную карму. Остаток старого оплаченного Озарения выдаётся один раз после восстановления техник/тиров; новые покупки начисляют XP сразу.
- **Регрессии**: `npm test` — логика, миграции и ограничения экономики; `npm run test:browser` — интерфейс и настоящие перезагрузки (Playwright/Chromium); `npm run balance:simulate` — четыре жизни с фиксированным RNG без debug-бонусов; `npm run balance:check` — пороговая проверка того же сценария. GitHub Actions запускает `npm test`, `npm run test:browser` и `npm run balance:check`.
- **Слухи**: adventureDiscovery, единый кулдаун и ожидание после доступности; сюжетные открытия помечены отдельно.
- **Экспедиции**: длительность, компенсация ци, диапазон Дао и множители ресурсов фиксируются при старте. Ци и годы медитации в пути не начисляются; успешное возвращение даёт ограниченную ци за духовный опыт. Старые слабые царства теряют ценность по ступеням. getDaoProgressRoom() ограничивает фактическую награду и UI; подробности в docs/expedition_balance_review.md.
- **Кнопки**: рендеры используют deferUIRender(), чтобы не заменять нажатый контрол; кеш пилюль сохраняет DOM при неизменной разметке.
- **Техники**: эффект рассчитывается через getTechniqueEffectBonus(); множитель тира зависит от ключа эффекта (силовая кривая/поддержка). UI использует тот же расчёт.
- **Приключения**: getAdventureCheck() объединяет игровые и видимые условия; поздняя сложность фиксирована данными сюжета, не статами героя.
- **Карма**: prestige.karmaSpent — фактические платежи; общая накопленная карма = свободная + оплаченная. Скидки не увеличивают её. Прежние траты по каталогу не реконструируются.
- **Зачётные жизни**: totalRebirths считает все перерождения; qualifiedRebirths — пик не ниже realm 3 и реальный прогресс от стартовой ступени. _startingRealmThisLife фиксируется после бонусов тела/кармы и сохраняется. При старте на Ядре достаточно одного успешного подуровня; неподвижная жизнь не зачётная. pendingRebirth кредитует qualifiedRebirths и bodyLives старого тела один раз. Корни, тела и Небесный Барьер используют зачётный счётчик.
- **Звёзды тела**: следующая ★ требует столько же зачётных жизней этим телом; цены сохранены. Свободный выбор открытых тел остаётся.
- **Ученики**: места по рангу 0/2/4/6/6, уровень до 10, XP 6/год. Все нанятые дают доход (40% базовой стипендии / 6 × навык) и пробуют разные готовые обычные задания; расходные/пожертвования ручные. Работ, отдыха и ручного первого освоения нет. Цены 20/45/90 со скидкой ранга, без накопительного удорожания. Два кандидата (Глаз даёт три), сроки обновления каждой позиции 30–60 лет; покупка оставляет пустое место до срока. Пределы жизни 100–200/150–400/300–700, начальный возраст 16–30. Смерть до XP/выплат; годовые отметки защищают от повторов. Состав теряется при уходе/перерождении.
- **Кармические разрешения**: Книга/Пересмотр/Расписание/Глаз требуют оплаченного уровня. Бесплатные численные уровни Архата их не открывают. Книга начинает обычную технику исходного тира и уровня 1; расписание не выполняет прорывы.
- **Корень**: getMinRootTier()/getAvailableRoots() учитывают минимум тела/вознесения. Выбор однократный, ручные элементы только открытые, без дублей.
- **Пилюли секте**: donate_pills_sect завершается автоматически после нужной сдачи, обе выплаты и общий кулдаун сохранены.
- **Язык**: весь UI и данные на русском. Комментарии к коду — на русском или английском

## Игровая петля

```
tick() [200ms]  — авто-ци, XP статов (пассивно 15%, активный 100%), XP техник и дробный XP учеников
passYear() [5s] — возраст++, доход камней, эпохи, мир.события, секта, годовой тик учеников, экспедиции, смерть
triggerEvent() [15s] — цепочки → манхва → обычные события
autoSave [30s]
```

## Прогрессия

- 15 реалмов (0-14), каждый × 4 подуровня. Реалмы 0-9 смертные, 10-14 бессмертные
- Prestige через перерождение: карма → тела → кармические апгрейды → формации
- Дао: прогрессивные требования прорыва с Золотого Ядра; подходящая активность зависит от секты
- Секты (5 шт) → ранги → техники → задания → вклад
- Артефакты: генерация → заточка +0..+10 → слияние PRI→PEN → вознесение техник

## Правила работы

1. **Читай prototype_report.md, architecture.md и mechanics.md** перед крупными изменениями — актуальные различия прототипа собраны в отчёте
2. **formulas.js — центр расчётов**. Не дублируй формулы в других файлах
3. **save.js** — при добавлении полей: state.js + reset() + getSaveableState() + applyLoadedState()
4. **Обновляй CHANGELOG.md** при значимых изменениях (текущая версия0.7)
5. **Обновляй docs/** если меняешь механики, архитектуру или баланс
6. **Тестируй в браузере** — открой index.html, используй дебаг-панель (скорость x10/x50/x100)
7. **Проверяй сохранение прототипа** — state/reset/save меняются вместе; загрузка сохраняет однократность наград и зачёта. Совместимость старых сохранений не является обязательным ограничением игрока. Прежние ключи читаются только для однократного переноса в текущий профиль; исходные копии не перезаписываются.
8. **Баланс**: смотри docs/game_balance.md для целевого пейсинга перед изменением чисел
9. **Бэклог**: актуальный список задач в `docs/backlog.md`. Отмечай `[x]` при завершении
