# Гайд по созданию контента: События и Приключения

## Философия

Игрок — не герой квеста. Он культиватор, проживающий жизнь. События и приключения — это моменты в этой жизни, а не задания из RPG.

Первую жизнь начинает обычный человек. Тела перерождения и поздние реалмы меняют его положение в мире — текст должен учитывать этот путь. Канон собственного мира задаёт `docs/worldbuilding.md`; `docs/lore_reference.md` — справочник вдохновения, его герой, Система и исключительные способности не становятся биографией игрока.

### Текст и правило игры

Перед написанием сцены зафиксируйте её контракт: кто участвует, почему она доступна, сколько времени проходит, что меняет каждый выбор и чем история заканчивается. Проверяйте этот контракт по `condition`, `check`, `cost`, `duration`, `success/fail` и фактическому обработчику наград.

- **Ситуация** описывает наблюдаемое: место, участника, препятствие.
- **Кнопка** показывает намерение игрока. Её должно быть легко понять с первого чтения.
- **Описание** показывает существенный обмен: ресурс, время, проверку, доступ к знанию. Числа и индикаторы UI должны совпадать с движком.
- **Исход** описывает то, что действительно произошло. Не утверждайте, что игрок затопил нору, купил предмет или забыл технику, если соответствующей ветки/эффекта не было.

«Шанс техники» означает случайный бросок. Именованную гарантированную технику называйте прямо; если гарантия зависит от прежнего выбора, используйте функцию `description(flags)`. Минимальный тир, потеря ци и стоимость также могут зависеть от ветки. Для потери ци различайте процент текущего запаса и процент `qiNeeded()` — «от запаса для прорыва».

Годы ожидания задаёт `duration`. Финальное исследование вознесения с нулевой указанной длительностью занимает 20 лет по общему `getAdventureChoiceDuration(adventure, choice, outcome)`: его используют и исполнение, и UI. Если сроки успеха и провала различаются, показываются оба. Часы или дни допустимы в мгновенной сцене, но подпись «долго» без таймера вводит в заблуждение. Если в истории проходит восемь лет, следующий текст не должен говорить об одной ночи. «Раз в столетие», «через год», «навсегда» допустимы только при соответствующих календарных условиях и сроке сохранения прогресса. Мировой год и возраст персонажа различаются.

## СОБЫТИЯ

### Типы событий

| Тип | Цель | Награда | Пример |
|-----|------|---------|--------|
| Филлер | Атмосфера, ощущение живого мира | Ничего / 2-3% ци / 2-3% дао | "Кот с двумя хвостами спал на камне" |
| Наградный | Прогрессия через случайность | +стат / ресурсы / шанс техники | "Бродячий лекарь ткнул иглой в шею" |
| Опасный | Напряжение, риск/награда | Успех: +стат/ресурсы. Провал: -ци/-стат | "Надменный юнец перегородил дорогу" |
| Follow-up | Мир помнит, NPC возвращаются | Зависит от первого события | "Тот торговец теперь в богатых одеждах" |

### Система чеков: `_eventCheck(playerStat, threshold)`

```
chance = 0.85 + min(0.10, playerStat / threshold * 0.10)
```

- Стат = 0 → 85% пройти
- Стат = порог → 95%
- Стат >> порога → 95% (кап)
- **Всегда 5-15% провала** — даже сильный игрок может проиграть

Использовать для вероятностных проверок обычных событий. Приключения и сюжетные цепочки могут использовать жёсткий порог: тогда UI должен честно показывать условие. Не заменять гарантированную сюжетную проверку случайностью ради единообразия.

### Именные NPC: `_rname(female?)`

- Генерирует случайное xianxia-имя из пула (20 фамилий × 15 имён)
- Имя сохраняется во `flags` первого события, читается из `flags` в follow-up
- Случайным прохожим подходит `_rname()`. Повторная встреча читает то же имя из флага, не генерирует новое.
- Именованные сюжетные персонажи сохраняют свои имена: Чжоу Вэй, Мастер Юнь, Старейшина Лю, Грид. Их связанные события и приключения используют одну биографию и географию.
- Возраст и описание NPC должны согласовываться: седой мечник через шестьдесят лет может стать сильнее, но не «возмужать» как юноша. Причину долгой жизни показывайте, когда она важна для сцены.

### Кулдаун филлеров

```javascript
condition: (g) => g.realmIndex >= X && g.years - (g.flags._cd_eventId || 0) >= 50,
effect: (g) => {
    g.flags._cd_eventId = g.years;
    // ...
}
```

50 лет — обычный кулдаун атмосферных филлеров. Проверяйте плотность доступного пула для каждого диапазона реалмов; общее число событий не означает, что они все доступны одному персонажу.

### Правила наград в событиях

1. **Филлеры**: 0 статов. Максимум 2-3% ци или 2-3% дао (если realm >= 3 и есть секта)
2. **Наградные**: +1 стат допустимо, но не в каждом. Ресурсы соответствуют доступному диапазону реалмов и ценности источника; повторяемая ранняя сцена не должна становиться главным источником поздних материалов
3. **Опасные**: Успех = +стат или ресурсы. Провал = -ци (10-20%). Никогда -стат за danger если это не boss-уровень
4. **Follow-up**: Возвращает последствия первого события. Более ценная награда уместна для сюжетного завершения; атмосферная повторная встреча может обходиться без лута
5. **Дао даётся только при realm >= 3 и наличии секты** (иначе бесполезно)

Случайный свиток выбирает кандидата через `g.getRewardTechniquePool()` или `g.getRewardTechniquePool(["common", "uncommon", "rare"])`. Этот helper исключает изученные техники, требования недоступного реалма и источники `sect`, `body`, `adventure`. Именованное наследие выдаёт `learnTechnique(id)` только в своей сюжетной ветке. Нельзя обещать артефакт, если эффект выдаёт пилюли; нельзя показывать придуманное постоянное улучшение вместо временного прироста ци. Расчётные суммы в логе берутся из реально начисленной награды с её множителями и ограничениями.

Метка `source: "chain"` сама по себе не делает технику эксклюзивной: действующий случайный пул её допускает при выполнении требований. Если новый контент требует строгого собственного источника, это нужно выразить согласованным типом источника, а не только названием техники или комментарием.

### Правила текста в событиях

1. **Конкретика > абстракция**: "Мужик в рваном халате лежал в канаве" > "Вы встретили культиватора"
2. **Сенсорные детали**: запах, звук, температура. "Запах мокрой земли", "стук дождя по черепице"
3. **Финал с характером**: "Мудрый зверь. Вы почувствовали, что вас оценили... и признали неинтересным"
4. **Юмор дозирован**: 1 смешное событие на 4-5 серьёзных
5. **Без обещаний продолжения**: если нет follow-up — не намекать на него. "Старая карта, ведёт в никуда" = плохо

### Аномальные филлеры (реалм 5+)

Отдельная категория — лёгкий сюр/хоррор без наград:
- "Шаги впереди вас"
- "Тень сделала лишний шаг"
- "Дверь без стен"
- Привязывать к `totalRebirths >= 1` когда уместно (чужая память, человек который помнит)
- **8 из 10 без награды**, максимум 2 с +2-3% ци

## ПРИКЛЮЧЕНИЯ

### Структура

- Обычно 2–4 шага, содержательная развилка — 2–3 варианта. Получение результата или завершение истории может иметь одну кнопку
- Каждый шаг: `text` (ситуация) + `choices[]` (варианты)
- Варианты: `text` (кнопка) + `description` (пояснение) + `check/cost/duration` + `success/fail`

### Кнопки: понятное намерение

Короткое «Войти в воду» может быть лучше длинной философской реплики, если точно передаёт выбор. Характер и сомнение помогают там, где раскрывают мотивацию; не нужны для каждой кнопки. Не скрывайте цену или риск за метафорой.

| Плохо (RPG-язык) | Хорошо (наш стиль) |
|---|---|
| "Ударить первым" | "Шагнуть вперёд, не раздумывая" |
| "Подкупить стража" | "У каждого турнира есть изнанка. Найти её" |
| "Разнести голема" | "Три тысячи лет он стоял. Достаточно" |
| "Нанять проводника" | "Заплатить тому, кто знает гору лучше вас" |
| "Пробить формацию грубой силой" | "Четыре тысячи лет — а всё равно это просто камни" |
| "Медитировать на берегу" | "Ничего не делать. Озеро старше вас. Пусть решает" |
| "Сдаться" | "Поклониться и отступить. Не каждый бой нужно принимать" |

### Приёмы для кнопок

- **Сомнение**: "...даже если это ошибка", "...что бы это ни значило"
- **Философия**: "Свет против тьмы. Классика, которая работает"
- **Характер**: "Мёртвым не нужны сокровища. А вам — нужны"
- **Недеяние**: "Ничего не делать. Сесть и ждать" — с реальным результатом

### Неожиданные исходы

Игрок быстро учит: быстро=риск, долго=безопасно, дорого=гарантия. Нужно иногда ломать:

1. **"Долго" = хуже**: ждать в гробнице → наследие рассыпалось, награды вдвое меньше
2. **"Безопасно" = ловушка**: медитация у озера → двойник подготовился, чеки выше
3. **"Глупо" = лучший**: разбить зеркало иногда даёт неожиданный результат

Это ориентир разнообразия, а не квота. Неожиданный исход должен иметь след в исходной ситуации: ненадёжный продавец, трескающаяся печать, подвижное отражение. Не скрывайте неизбежный большой штраф под подписью «безопасно».

### Различие выборов

Для каждой кнопки запишите, что она меняет в текущем или следующем шаге: проверку, время, ресурсы, информацию или отношение персонажа. Если платный путь имеет тот же исход, что бесплатный путь без проверки и ожидания, цена пока не имеет игрового смысла. Такой выбор нужно исправить в отдельном проходе по механикам, а не оправдывать туманным текстом.

Нарративные различия тоже допустимы, но описание должно обещать именно их. Бесплатные, безопасные и медленные пути сохраняют ценность; усиление проверки на следующем шаге объясняется текстом. Каждая fail-ветка проверяется отдельно — общий `else` не должен описывать действие другой кнопки.

### Кнопка "ничего не делать"

Иногда добавлять вариант бездействия с реальной наградой:
- Храм: "Поклониться и уйти. Это чужое наследие" → +3 дух, 0 лута
- Турнир: "Не каждый бой нужно принимать" → +2 дух
- Сад: "Ждать 30 лет. Пусть сад сам решит" → лучший исход

### Динамические чеки и описания

`check`, `cost` и `description` могут быть функциями от `adventure.flags`:

```javascript
check: (flags) => ({ combatPower: flags.meditated ? 30 : 22 }),
description: (flags) => flags.meditated ? "Двойник подготовился" : "Нужна боевая мощь",
cost: (flags) => flags.village ? {} : { stones: 20 },
```

Это позволяет выбору на шаге 1 влиять на сложность и цену шага 2 — и игрок видит это в UI. Такие функции должны только читать флаги и возвращать данные: превью тоже их вызывает. `check: null` снимает проверку, а отсутствие `fail` при непрошедшей проверке блокирует выбор без списания цены. Отдельно проверьте, что информация действительно выгоднее доступного бесплатного пути; одной смены рассказа для платного выбора недостаточно.

### Провалы

- Часть провалов открывает другой результат: меньше лута, но опыт, иной проход или новая информация.
- Тяжёлый штраф подходит серьёзному риску, который игрок мог оценить до выбора.
- Текст провала должен быть таким же атмосферным как текст успеха

### Награды в приключениях

| Тип | Что давать |
|-----|-----------|
| Early (реалм 2-6) | Камни 15-80, пилюли 1-5, эссенция 5-40, шанс техники 10-35%, шанс артефакта |
| Mid (реалм 5-9) | Эссенция 15-120, пыль 5-60, свитки дао 20-50%, артефакт uncommon-rare, дао-прогресс 5-15% |
| Late (реалм 7-12) | Эссенция 30-200, пыль 15-100, свитки дао 25-60%, артефакт rare-epic, дао-прогресс 5-20%, +2-4 статы |

Это ориентиры базовых наград, не универсальная формула и не гарантия для каждого исхода. Актуальные ограничения множителей, повторной выдачи и экономический смысл источников проверяются по `docs/game_balance.md` и общим игровым helper-методам.

**Fillerные награды**: пыль, эссенция, свитки дао. НЕ камни и НЕ пилюли (их и так хватает).

### Приключения без боя

Минимум 1-2 приключения где сила/combatPower бесполезны:
- Рынок Теней — торговля и блеф
- Наставник из Тумана — обучение и терпение
- Зеркальная Библиотека — чтение и отражения

### Эхо-события

После завершения приключения — 1 событие-эхо в основном пуле:
- Лис из каравана на крыше рынка
- Не для каждого приключения — только для самых запоминающихся (1-2 штуки)
- Чисто атмосферные, без наград

### Задел на будущее

Приключения могут ставить флаги для будущих систем:
- `dao_tree_seed` — семя Древа Дао из Сада Бессмертных
- `grid_wants_apprentice` — Грид хочет стать учеником
- `spirit_beast_healed` — кармическая связь со зверем

Флаги текущей жизни хранятся в `game.flags` и сбрасываются при перерождении. Внутренний флаг не является наградой для игрока: не показывайте «флаг на будущее» в описании кнопки. Семя или просьба NPC могут завершать сцену как сюжетная деталь, но не должны обещать доступную функцию, которой пока нет.

Постоянные последствия требуют отдельного согласованного поля prestige и его сохранения/сброса/миграции. `permanentMilestones` предназначен для зарегистрированных достижений, не для произвольных сюжетных флагов. Один факт — одна история: альтернативный путь к наследию или уникальному трофею проверяет, не получен ли он ранее.

## Чеклист перед добавлением

### Событие:
- [ ] Текст конкретный, с деталями (не "вы встретили культиватора")
- [ ] Condition проверяет ресурсы перед тратой (stones >= X в condition если effect тратит камни)
- [ ] _eventCheck вместо жёстких порогов
- [ ] Именные NPC через _rname(), имя сохранено в flags для follow-up
- [ ] Филлер: 0 статов, макс 3% ци/дао
- [ ] Не обещает продолжения которого нет
- [ ] Сроки, NPC, секта и названия мест согласованы с условиями и связанными сценами
- [ ] Описание и лог награды соответствуют фактически выданным предметам и суммам
- [ ] Случайная техника взята из общего допустимого пула, сюжетная — из собственного источника

### Приключение:
- [ ] Кнопки = намерение, не действие
- [ ] Description короткий (не дублирует текст кнопки)
- [ ] Нет "очевидно правильного" выбора
- [ ] Провалы атмосферные, не только "-X стат"
- [ ] Награды соответствуют тиру (early/mid/late)
- [ ] Разнообразие исходов уместно для сцены, неожиданный исход заранее допускается её деталями
- [ ] Каждый выбор имеет понятный смысл; платный путь не дублирует бесплатный без преимущества
- [ ] Проверены все success/fail-переходы, в том числе динамический текст после провала
- [ ] Часы/годы в тексте совпадают с таймером; шанс, гарантия и минимальный тир названы верно
- [ ] После JSON save/load исход и выдача повторяются корректно, уникальная награда не дублируется
